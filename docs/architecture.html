System Architecture

Factory Inventory Management System

A full-stack inventory, orders, and finance dashboard demo. A Vue 3 single-page app talks over HTTP to a read-only FastAPI service that serves filtered and aggregated views of static JSON datasets held entirely in memory — no database.

Vue 3 SPA FastAPI In-memory JSON data Read-only API Ports 3000 / 8001

01 System Architecture

Three layers: the browser client, the API service, and the data layer. Everything runs locally; state lives in memory for the lifetime of each process.

Notable: No database and no persistence — data resets on restart. The API is entirely read-only (a CreatePurchaseOrderRequest model exists but no write endpoint uses it). State management on the client is module-scoped composable singletons rather than Pinia/Vuex, and the backend URL is hardcoded with no Vite proxy.

03 Data Flow

A single request cycle, from a user changing a filter to rendered data on the page.

1
User sets a filter
FilterBar updates useFilters refs (period, location, category, status)
→
2
View reloads
getCurrentFilters() → api.js maps to warehouse / category / status / month
→
3
HTTP GET
axios sends query params to :8001/api/…
→
4
Filter in memory
FastAPI runs apply_filters / filter_by_month over the loaded lists
→
5
Validate & respond
Pydantic models shape the JSON response
→
6
Render
View stores raw data in refs; computed props derive charts & tables
The 4 global filters — period, warehouse, category, status — travel as query params. /api/inventory honors only warehouse + category (no time dimension); /api/orders and /api/dashboard/summary honor all four. Spending and report endpoints take no filters and aggregate the full dataset.
